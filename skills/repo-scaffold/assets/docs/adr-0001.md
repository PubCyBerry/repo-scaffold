# 0001. Record architecture decisions

## Context and problem statement

Architecture choices in {{REPO_NAME}} outlive the discussion that produced them. A few months
on, the code shows what was chosen but nothing shows why, which options were weighed, or what
the choice cost. Whoever arrives next either repeats the analysis or reverses the decision
without knowing what it was protecting.

Chat threads and pull request comments do not survive as an answer. They are not indexed with
the code, they are not linked from the documentation, and they disappear behind whichever tool
the team stops paying for.

## Considered options

| Option | Why not |
| --- | --- |
| Leave reasoning in pull request discussions | Not linked from the code, and lost when the host changes |
| One long design document per system | Rewritten in place, so the reason for an old choice is overwritten |
| A wiki outside the repository | Drifts from the code, and no check can compare the two |
| Numbered decision records in the repository | Chosen. See below |

## Decision outcome

Record every architecture decision as its own document under
[docs/architecture/adr/](index.md), numbered in the order the decisions are taken.

A record is written once and then left alone. When a decision stops holding, a new record
supersedes it: the new record lists the old `id` in `supersedes`, and the old record's
`status` becomes `superseded`. The body of the old record is never edited, because its value
is that it says what was believed at the time.

The format follows [MADR](https://adr.github.io/madr/) in outline and drops the parts that go
unused here. Four headings: context and problem statement, considered options, decision
outcome, consequences.

Records live in the repository so that they move with the code, appear in review diffs, and
are covered by the same checks as every other document. Metadata and placement follow
[Documentation](../../standards/documentation.md), which the checks in
[tests/check-docs.sh](../../../tests/check-docs.sh) and
[tests/check-docs-metadata.sh](../../../tests/check-docs-metadata.sh) enforce.

## Consequences

What this makes easier:

- A reviewer can cite a record instead of restating an argument
- An agent reading the repository finds the reasoning without being told it exists
- Reversing a decision becomes a deliberate act with a written cost

What this makes harder:

- Every decision worth recording adds a document and a row in
  [the index](index.md). Records that nobody writes are worse than no directory at all
- The number sequence has to be managed by hand. Two branches that add a record at the same
  time collide, and one of them renumbers

What is now fixed:

- Numbers are never reused, so a link to record 7 always means the same document
- A record's body is immutable once its status leaves `proposed`. Only `status` and
  `supersedes` change after that
