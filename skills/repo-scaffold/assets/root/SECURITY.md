# 보안

자격 증명, 비밀값, 민감정보 취급 규칙. 이 저장소 전체에 적용한다.

이 문서의 규칙은 다른 규칙보다 우선한다. 편의를 이유로 예외를 두지 않는다.

## 원칙

1. 비밀값은 `.env` 에만 둔다. 다른 어디에도 리터럴로 쓰지 않는다.
2. 남는 곳에 흘리지 않는다. 로그, 명령 인자, 커밋, 문서, 에이전트 출력이 대상이다.
3. 지웠다고 사라지지 않는다. 커밋에 한 번 들어간 토큰은 이력에 영구히 남는다.
   들어갔으면 즉시 폐기하고 재발급한다.

## 자격 증명 저장

| 위치 | 내용 | 커밋 |
| --- | --- | --- |
| `.env` (저장소 루트) | 토큰, API 키 등 실제 값 | X (`.gitignore` 대상) |
| [.env.example](.env.example) | 키 이름만. 값은 비움 | O |
| `<컴포넌트>/.env` | 그 컴포넌트 런타임 설정 | X |

- 키를 추가하면 `.env.example` 에도 빈 값으로 동기화한다. pre-commit 훅 `env-sync` 가 검증한다
- 자격 증명은 저장소 루트 `.env` 한 곳에 모은다. 컴포넌트 `.env` 와 섞지 않는다
- 코드, 설정 파일, 문서, 스크립트에 토큰 리터럴을 넣지 않는다

에이전트 스킬은 저장소 루트에서 `.env` 를 읽는다.

```bash
set -a && . ./.env && set +a
```

`.env` 값을 확인할 일이 있으면 값이 아니라 키 이름만 본다.

```bash
grep -oE '^[A-Z_]+=' .env
```

## 토큰 전달

- 토큰을 remote URL 에 박지 않는다. `.git/config` 에 영구 저장되고 `ps` 출력에 노출된다
- REST 호출은 헤더로 넘긴다. URL 쿼리스트링에 넣지 않는다. 쿼리스트링은 서버 액세스 로그에 남는다
- 토큰을 명령 인자로 주지 않는다. 환경변수나 stdin 으로 넘긴다
- 토큰을 로그, 커밋 메시지, 이슈, 채팅에 붙여넣지 않는다

## 로그와 출력

다음은 로그, 표준 출력, 오류 응답, 에이전트 출력 어디에도 남기지 않는다.

- 비밀번호, API 키, 토큰, 세션 ID
- 개인식별정보(PII)
- UPDATE, DELETE 쿼리의 파라미터

오류 응답의 메시지는 엔드 사용자가 읽는 문장이다. 내부 구현, 경로, 쿼리를 노출하지 않는다.

## 공유 자원

원격 DB, 캐시, 스토리지는 공유 자원이다. 로컬 사본이 아니다.

- 화면이나 API 로 지운 데이터는 서버에서도 지워진다
- 파괴적인 작업 전에 담당자에게 확인한다
- 테스트용 데이터는 식별 가능한 접두어를 붙이고 끝나면 정리한다

## 커밋 전 확인

- `.env`, 토큰, PAT, 비밀번호, 인증서가 staged 에 없는가
- 새로 추가한 설정 파일이 `.gitignore` 로 덮이는가
- 로그 예시나 문서 본문에 실제 토큰값을 붙여넣지 않았는가

```bash
bash tests/check-secrets.sh    # staged 자격 증명 스캔. pre-commit 이 자동으로도 돈다
bash tests/check-env.sh        # .env 와 .env.example 키 동기화
```

스캔은 두 층이다. 아래층은 의존성이 없어 항상 돌고, 위층은 도구가 있을 때만 돈다.

| 층 | 검사기 | 대상 | 언제 |
| --- | --- | --- | --- |
| 아래 | `tests/check-secrets.sh` 의 패턴 스캔 | staged 내용, 패턴 10종 | 매 커밋 |
| 위 | `gitleaks` | 규칙 수백 종, 엔트로피 판정 | CI. 로컬은 깔려 있을 때만 |

`gitleaks` 는 CI 전용 도구라 `tools.txt` 에 없고, 없다고 커밋을 막지 않는다.
규칙은 `.gitleaks.toml` 에 있고 CI 와 로컬이 같은 파일을 쓴다.
오탐 한 줄을 넘기려면 그 줄 끝에 `secret-scan: allow` 와 `#gitleaks:allow` 를 붙인다.
넘기기 전에 값을 폐기했는지 먼저 확인한다. 넘기는 것은 값이 자격 증명이 아닐 때만이다.

## 유출 대응

토큰이 커밋, 로그, 문서, 채팅 어디로든 나갔으면 순서대로 처리한다.

1. 해당 토큰을 즉시 폐기한다. 되돌리기나 커밋 삭제보다 폐기가 먼저다
2. 새 토큰을 발급하고 `.env` 를 갱신한다
3. 노출 범위를 보고한다. 저장소, 브랜치, 채널, 시점을 적는다
4. 이력에서 제거할지는 그다음에 판단한다. 이미 push 된 이력은 강제로 다시 쓰지 않는다
